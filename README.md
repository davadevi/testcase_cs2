# CS2 Utility Analytics — POC

Proof-of-concept: что можно сказать игроку CS2 про его игру, имея только данные
о бросках гранат (10,000 матчей Premier/MM на Cache). Задача — `task.md`.

## Окружение

Зависимости и venv — через [Poetry](https://python-poetry.org/) (`pyproject.toml` / `poetry.lock`).

```bash
poetry install
poetry run python -m ipykernel install --user --name testcase-cs2 --display-name "Python (testcase-cs2 poetry)"
poetry run jupyter lab   # или открыть ноутбуки в IDE с ядром "Python (testcase-cs2 poetry)"
```

## Структура проекта

```
data/
  grenades_by_match_0726.list     # исходный pickle, 10k матчей
  processed/                       # кэш: flat parquet-таблицы + профиль бинов
notebooks/                         # 4 ноутбука, см. ниже
docs/                               # справочники и выводы, см. ниже
```

## Ноутбуки (`notebooks/`)

| Файл | Что внутри |
|---|---|
| `eda.ipynb` | Исходный разведочный анализ: разбор датасета поле за полем, парное сравнение признаков, корреляции по типам гранат. Строит кэш `data/processed/{throws,damage,flashed,players}.parquet`, который читают все остальные ноутбуки. |
| `player_utility_analysis.ipynb` | Best-case демонстрация: разбор одного игрока с максимумом доступных данных (9 матчей, 310 бросков) — микс гранат, эффективность флешей/HE/молотова, консистентность смок-лайнапов (DBSCAN), тайминг по раунду, выводы с конкретными рекомендациями и ссылками на инструменты SCOPE.GG. |
| `rating_cohort_analysis.ipynb` | Популяционный анализ: все пары «игрок–матч» с известным рейтингом (24.4% датасета) бьются на 5 квантильных бинов, для каждого бина считается профиль по 17 утилити-метрикам с 95%-ным доверительным интервалом. Экспортирует `data/processed/rating_bin_profiles.parquet`. |
| `player_rating_bin_report.ipynb` | Typical-case демонстрация: реалистичный игрок (медиана по активности — 2 матча, 53 броска) сравнивается с профилем своего рейтинг-бина; если рейтинга нет — бин оценивается по поведению (нестрогая оценка, см. ниже). |

Зависимость: `eda.ipynb` → кэш parquet → `rating_cohort_analysis.ipynb` → `rating_bin_profiles.parquet` → `player_rating_bin_report.ipynb`. `player_utility_analysis.ipynb` зависит только от кэша `eda.ipynb`.

## Главные результаты

**Утилити почти не разделяет рейтинговые бины.** Из 17 метрик только `nades_per_round`
(гранат за раунд) показывает содержательную разницу между низким и высоким бином
(размах ≈0.6 внутрибинового std). Остальные 16 — слабые разделители (<0.3, многие <0.1).
Поведенческая оценка бина без рейтинга угадывает точно в ~26% случаев против ~20% случайных —
заметно лучше угадайки, но далеко не замена рейтингу.

**Что при этом работает хорошо:**
- явные нулевые/пустые броски (0 урона по HE/молотову, пустые флешки) — метрика считается
  точно и не зависит от шума выборки (в отличие от сравнения с рейтинг-бином), но это повод
  присмотреться, не диагноз. "0 урона" выглядит одинаково и для броска в молоко, и для
  осознанного броска, где врага просто не оказалось, и для меткого броска, от которого враг
  успел уйти — отличить эти случаи без позиции врага до момента урона невозможно (датасет
  её не содержит). Высокая доля таких бросков — сигнал "стоит пересмотреть в Demo Viewer",
  не готовый вывод "кидает бездумно";
- частота использования утилити (`nades_per_round`) — единственная метрика с реальной
  разделимостью по скиллу;
- консистентность смок-лайнапов (DBSCAN по точкам броска + разброс точки приземления) —
  рабочий прокси «заучен лайнап или кидается на глаз».

**Ограничение, которое нельзя обойти на этом датасете:** нет временной метки реальной игры
(единственный кандидат, `_id`, несёт время bulk-экспорта в базу — все 10,000 записей созданы
в пределах секунды). Трекинг игрока относительно самого себя во времени — более надёжный
сигнал, чем сравнение с чужим рейтинг-бином, и так и работает реальный SCOPE.GG Dashboard
("My Progress") на настоящих данных — но на этом снэпшоте продемонстрировать нельзя.

**Что это доказывает как POC:** pipeline «данные → метрики → бины → сравнение игрока →
рекомендации со ссылкой на реальные инструменты» работает и честно проверяет сам себя на шум
(доверительные интервалы, accuracy классификатора против chance-уровня), а не выдаёт
переобученную уверенность там, где сигнала почти нет. Подробности — `docs/poc_findings_summary.md`.

### Текущих данных недостаточно, чтобы полноценно советовать игроку, как расти

Скилл в CS2 — не одна ось, а несколько слоёв, и каждый следующий имеет вес только
после предыдущего:

1. **Стрельба (aim/спрей/позиционирование под дуэль)** — решает большую часть
   результата на всех уровнях игры. Про неё в датасете нет вообще ничего
   (ни хитов, ни выстрелов).
2. **С определённого уровня** к стрельбе добавляется **знание гранат, движения
   по карте и таймингов** — то, что мы и пытались анализировать. Про гранаты
   данных достаточно; про движение (вне момента броска) и реальные тайминги
   раунда (без привязки к экономике/коммуникации) — нет.
3. **На уровнях выше** всё это дополняется **стратегией** (ауты, понимание стиля игры противников, командные решения) — данных об этом нет вообще ни в каком виде.

**Следствие:** на одной утилити нельзя дать игроку исчерпывающий совет "как расти" —
это в лучшем случае один из трёх слоёв, причём не первый по весу. Будь в датасете
стрельба, тайминги бросков относительно реального старта раунда и движение по карте —
выводы были бы кратно информативнее (видно было бы, например, не просто "кидаешь HE
в пустоту", а "кидаешь HE в пустоту именно потому, что плохо читаешь позицию
противника до броска").

При наличии всего этого можно было бы делать не только всё перечисленное выше, но и
**аналитику по каждому конкретному матчу с разбором стиля игры каждого игрока** —
это сложная система, потому что правильное решение зависит от контекста, а не
универсально: если на карте у соперника люркер — играть нужно одним образом; если
соперники легко стягиваются и реагируют на фейк-раскидку — другим; если они кидают
гранаты рано и щедро тратят утилити на каждый раунд — третьим. При наличии данных о
стрельбе, таймингах и движении эти поведенческие паттерны можно было бы увидеть в игре
конкретного игрока/команды и дать предметную оценку: похвалить за верное решение под
конкретную ситуацию или объяснить, как нужно было сыграть иначе именно в этом матче или даже в конкретном раунде —
а не усреднённый совет "кидай меньше пустых флешек".

**Но и в рамках того, что есть, пользу извлечь можно** — POC это показывает на
`player_rating_bin_report.ipynb`: для обычного игрока с 2 матчами и 53 бросками
выведен честный человекочитаемый отчёт (раздел 9.3 этого ноутбука) с конкретными цифрами по его же броскам ("45% твоих HE не нанесли
урона, у игроков твоего уровня — 63%") и прямой ссылкой, каким инструментом SCOPE.GG
это поправить (Grenade Predictor, Demo Viewer, CS2 Dashboard → My Progress, Comparing
tool), плюс честная сноска о приблизительности оценки. Это нижняя, но рабочая
граница того, что можно сделать на одной утилити.
