# Справочник метрик

Все метрики, используемые в `notebooks/player_utility_analysis.ipynb`,
`notebooks/rating_cohort_analysis.ipynb`, `notebooks/player_rating_bin_report.ipynb`.
Единицы и edge-cases указаны явно, т.к. из названия колонки они не всегда очевидны.

## 1. Метрики на уровне одного броска (`throws`, после join с `damage`/`flashed`)

Эти колонки добавляются к таблице бросков во всех трёх аналитических ноутбуках (с небольшими
вариациями имён между `player_utility_analysis` и остальными двумя — указано отдельно).

| Колонка | Тип гранаты, для которой определена | Значение |
|---|---|---|
| `enemy_dmg` | HE, molotov | Урон по здоровью врагов от этого броска (сумма `health_dmg` из `DamagedPlayers`, только `rel == 'enemy'`). `0`, если бросок есть, но никого не задел; `NaN` для smoke/flash — у них этой величины физически нет. |
| `enemy_armor_dmg` | HE, molotov | Урон по броне врагов, аналогично `enemy_dmg`. |
| `dmg_total` | HE, molotov | `enemy_dmg + enemy_armor_dmg` (только в `rating_cohort_analysis` / `player_rating_bin_report`). |
| `n_enemies_hit` | HE, molotov (только в `player_utility_analysis`) | Сколько разных врагов получили урон от броска. |
| `enemy_kills` | HE, molotov (только в `player_utility_analysis`) | Сколько врагов убито этим броском (`killed` из `DamagedPlayers`). |
| `n_flashed_enemy` | flash | Сколько врагов ослеплено этой флешкой (`rel == 'enemy'` в `FlashedPlayers`). |
| `n_flashed_team` | flash | Сколько тиммейтов (не считая себя) ослеплено этой флешкой. |
| `n_flashed_self` | flash (только в `player_utility_analysis`) | Ослепил ли бросок самого бросавшего (0/1). |
| `n_flashed_own` | flash (только в `player_utility_analysis`) | `n_flashed_team + n_flashed_self` — все "свои", включая себя. |
| `enemy_blind_s` | flash (только в `player_utility_analysis`) | Суммарная длительность слепоты, нанесённая врагам этим броском (сек, сумма `flash_duration`). |
| `flash_kills` | flash | Сколько ослеплённых этой флешкой врагов было убито (не обязательно тем же игроком). |
| `flash_kills_own` | flash (только в `player_utility_analysis`) | Из них — убито самим бросавшим (`killed_by == thrower_id`). |
| `zero_dmg` | HE, molotov | Булева метка: `enemy_dmg == 0` (бросок нанёс 0 урона). |
| `empty_flash` | flash | Булева метка: `n_flashed_enemy == 0` (никого из врагов не ослепила). |
| `t_in_round` | любой | Секунды от **первой гранаты, брошенной кем угодно в этом раунде**, до этого броска. **Это не время от начала раунда** — момент старта раунда в данных не записан, используется proxy (первая граната раунда = условный "0"). См. ограничения в разделе 2 каждого ноутбука. |

**NaN vs 0 для dmg/flash-колонок:** `NaN` означает "эта величина не определена для такого типа гранаты"
(у smoke нет урона и нет ослепления, у HE/molotov нет ослепления, у flash нет урона).
`0` означает "величина определена, но бросок сработал впустую". Их нельзя путать —
поэтому превью таблицы в ноутбуках теперь явно показывает по строке на каждый тип гранаты.

## 2. Метрики на уровне «игрок × матч» (используются в обоих рейтинговых ноутбуках)

Все считаются на пару (игрок, матч), затем усредняются по бину/игроку. Для метрик,
зависящих от типа гранаты, нужно минимум `MIN_N = 3` бросков этого типа у игрока в матче —
иначе значение `NaN` (слишком шумно на 1–2 броска).

| Метрика | Формула / смысл |
|---|---|
| `nades_per_round` | Всего гранат игрока за матч / раундов в матче. Раунды = максимальный номер раунда, где была граната, + 1 (т.к. номера раундов с 0). Определена всегда, даже если бросков 0. |
| `share_smoke`, `share_flash`, `share_he`, `share_molotov` | Доля бросков этого типа среди всех бросков игрока в матче. Требует ≥3 бросков **любых** типов в матче. |
| `flash_enemies_per_flash` | Среднее число ослеплённых врагов на одну флешку игрока в этом матче. |
| `flash_team_per_flash` | Среднее число ослеплённых тиммейтов (без себя) на флешку. |
| `flash_empty_share` | Доля флешек игрока, не ослепивших ни одного врага. |
| `flash_kills_per100` | Убийства ослеплённых врагов на 100 флешек игрока (нормировка для сравнимости между игроками с разным числом бросков). |
| `he_dmg_per_throw` | Средний урон (HP + броня) по врагам на один HE-бросок. **0 урона не обязательно плохой бросок** — в зоне взрыва в этот момент могло просто не быть врагов; позиций врагов вне моментов урона/ослепления в датасете нет, поэтому промах от «пустой» зоны не отличить. |
| `he_zero_share` | Доля HE-бросков с нулевым уроном по врагам. |
| `molotov_dmg_per_throw` | То же, что `he_dmg_per_throw`, для молотовых. **0 урона не всегда плохо** — молотов может использоваться для area denial (перекрытие зоны), не только для килла/урона. |
| `molotov_zero_share` | Доля молотовых с нулевым уроном. |
| `t_in_round_smoke`, `t_in_round_flash`, `t_in_round_he`, `t_in_round_molotov` | Среднее `t_in_round` (см. раздел 1) по броскам этого типа у игрока в матче — насколько рано/поздно в раунде (от первой гранаты раунда) игрок обычно кидает этот тип. |

Все 17 метрик (`nades_per_round` + 4 `share_*` + 4 `flash_*` + 2 `he_*` + 2 `molotov_*` + 4 `t_in_round_*`)
экспортированы как центроиды бинов в `data/processed/rating_bin_profiles.parquet`
(схема файла — в `rating_cohort_analysis.ipynb`, раздел 11).

## 3. Метрики сравнения игрока с бином (только `player_rating_bin_report.ipynb`)

| Метрика | Формула / смысл |
|---|---|
| `POOLED_STD` (объединённое std) | `sqrt(Σ(n−1)·std² / Σ(n−1))` по 5 бинам — стандартное отклонение признака "внутри бина", усреднённое по всем бинам с весом на размер выборки. Используется как единица измерения расстояния игрока от центроида. |
| `SEPARATION` (размах / std, "сила" признака) | `(max(центроиды бинов) − min(центроиды бинов)) / POOLED_STD` — размах между самым высоким и самым низким центроидом среди всех 5 бинов (не обязательно B5 и B1 — для немонотонных признаков экстремум может быть в середине), в стандартных отклонениях. Чем больше — тем надёжнее признак для различения бинов. У `nades_per_round` это ~0.61 (здесь максимум совпадает с B5, минимум с B1); у большинства остальных <0.3 (слабые разделители). |
| `WEIGHTS` (вес признака) | `SEPARATION / Σ SEPARATION` — доля влияния признака при расчёте итогового расстояния до бина. Сильные разделители (напр. `nades_per_round`) получают больший вес. |
| `DIRECTION` | Знак `(центроид B5 − центроид B1)` — растёт ли признак от низкого рейтинга к высокому (+1) или падает (−1). Используется, чтобы понять, "в какую сторону" отклонение игрока. |
| Взвешенное расстояние до бина | Для каждого бина: `sqrt(Σ WEIGHTS · ((игрок − центроид) / POOLED_STD)² / Σ WEIGHTS по доступным признакам)`. Присвоенный бин — с минимальным расстоянием. Учитывает только признаки, которые определены у игрока (NaN пропускаются, веса перенормируются). |
| `z (в объед. std)` | `(значение игрока − центроид бина) / POOLED_STD` — на сколько стандартных отклонений игрок отличается от центроида референсного бина по конкретному признаку. |
| `надёжность` | Флаг в итоговой таблице: `«ок»`, `«мало данных»` (бросков типа < порога `LOW_N_THROWS` или матчей с признаком < 2), `«нет данных»` (признак не определён вообще). |

**Важно:** точность поведенческой оценки бина (без известного рейтинга) проверена на 3,141 игроках
с известным рейтингом — угадывает точный бин в ~26% случаев (случайно — ~20%), ±1 бин — в ~54%
(случайно — ~45%), и систематически смещена к крайним бинам (B1/B5). Это не точный рейтинг,
а грубая оценка — так и преподносится в ноутбуке 2.

## 4. Бины рейтинга

- 5 квантильных бинов (`pd.qcut`) по `PremierRatingNew` среди пар «игрок–матч» с известным рейтингом
  (24.4% всех пар). Границы и численность — в `rating_cohort_analysis.ipynb`, раздел 3.2.
- Названы `B1` (самый низкий рейтинг) … `B5` (самый высокий) — это не привязка к рангам CS:GO,
  просто 5 равнонаселённых групп на этом датасете.
- Распределение рейтинга унимодальное без естественных разрывов, поэтому границы — чисто
  статистические (равные по численности группы), не содержательные пороги.
